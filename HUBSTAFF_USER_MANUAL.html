1. Overview

The CI-ION Policy App is the home health agency's internal compliance and policy management system. The Hubstaff Staging feature lets you push all 199 compliance tasks across 5 Hubstaff projects — without ever accidentally creating duplicates, and with full control over exactly which tasks get pushed.

1
Stage
Review all tasks. Select or deselect by project or individually.
2
Review
Confirm exactly what will be created. Set your Org ID.
3
Push
Live progress bar. See each task created in real time. Abort anytime.
4
Done
Full report: created, skipped, failed. New project IDs to save.
Key principle: The system is idempotent — you can run it multiple times safely. Tasks that already exist in Hubstaff are automatically detected and skipped. No duplicates, ever.

2. Prerequisites

  • Node.js v18 or higher — nodejs.org
  • npm v9 or higher (included with Node.js)
  • Hubstaff account with at least one organization
  • Hubstaff Personal Access Token (PAT) — see Section 4
  • Internet connection (to reach the Hubstaff API)
First-time setup: Before you can push any tasks, you must add your Hubstaff PAT to the .env file. See Section 4.

4. Hubstaff Personal Access Token Setup

Step 1 — Generate Your PAT

  1. Log in to app.hubstaff.com
  2. Click your avatar (top right) → Preferences
  3. Go to Apps & API → Personal Access Tokens
  4. Click Create Token
  5. Give it a name: CI-ION Policy App
  6. Enable scopes: Hubstaff (read + write) and Hubstaff Tasks (read + write)
  7. Leave DPoP token blank — it is optional and not required here
  8. Click Create and copy the token immediately
Important: Copy the token now. Hubstaff will not show it again after you navigate away.

Step 2 — Add to .env

Open C:\AI\Git\training\HomeHealth\Policies_and_Procedures\.env in any text editor and add:

HUBSTAFF_PAT=your_actual_token_here
HUBSTAFF_ORG_ID=your_org_id_here

Step 3 — Find Your Org ID

The Org ID is automatically fetched when you open the Hubstaff page. It will be shown in the Review phase as a clickable button. You can also run the finder utility:

cd C:\AI\Hubstaff
npx tsx find-org.ts

Step 4 — Restart the Server

After editing .env, close and reopen the app (or close the API Server window and rerun npm run server).

5. Hubstaff Staging — What It Does

The staging page is your control center for managing all 199 tasks across 5 Hubstaff projects. It is designed to be safe to use repeatedly — the system always checks what already exists in Hubstaff before pushing.

What happens when you push?
  • For projects without a Hubstaff ID, a new Hubstaff project is automatically created
  • The system fetches all existing tasks from each project and compares by Task ID
  • Tasks that already exist are skipped (not duplicated)
  • New tasks are created with a 150ms delay between each to respect Hubstaff rate limits
  • All new project IDs are shown at the end so you can save them to .env

6. Phase 1 — Stage

This is the main view when you open the Hubstaff page.

Layout

  • Left column — Project tabs. Each shows task count and how many already exist in Hubstaff.
  • Right column — Tasks for the selected project, grouped by category. Each task is expandable.
  • Top bar — Live selection summary and the "Review & Push →" button.

Selecting Tasks

  • Click any task row to toggle its checkbox on/off
  • Select all / None buttons at the top of each project's task list to bulk-select
  • Tasks marked ALREADY EXISTS are grayed out and cannot be selected — they will always be skipped

Expanding a Task

Click the chevron arrow (▾) on the right side of any task row to expand it and see:

  • Full description text
  • Regulatory citation (e.g., 42 CFR §484.60)
  • Due date (if set)

Risk Badges

Each task displays a risk level badge:

CRITICAL Survey-deficiency risk, regulatory violation risk
HIGH Important compliance items
MEDIUM Standard operating tasks
LOW Informational / documentation

Connection Status

The top bar shows a green dot ● and your Hubstaff username when authentication is successful.

If it shows a red error, see Troubleshooting.

7. Phase 2 — Review & Confirm

Click "Review & Push →" to proceed to the confirmation screen.

What You'll See

  • Total count: X tasks will be created · Y already exist and will be skipped
  • Org ID selector — your organizations are listed as clickable buttons. Click the correct one.
  • Each project with a summary of tasks to be created and whether it will be auto-created or use an existing ID

Auto-Create vs. Existing Project

Projects that don't have a Hubstaff ID yet will show an auto-create badge. This means a brand-new Hubstaff project will be created under your organization when you push. Projects that already have an ID (like the Reg. Calendar project #3988878) will use the existing project.

Org ID required for auto-create. If you have projects that need to be auto-created, you must select your Organization ID before clicking Push.

Proceeding

Click "Push X Tasks" to begin. The button is disabled if no tasks are selected or if Org ID is empty.

8. Phase 3 — Pushing

Watch the live progress:

  • Large percentage — overall progress
  • Created counter (green) — tasks successfully pushed to Hubstaff
  • Failed counter (red) — tasks that encountered an API error
  • Current task — name of the last task processed

Aborting

Click the "Abort" button to stop mid-push. Tasks already pushed will remain in Hubstaff. Rerun the push later — the idempotency system will skip what was already created and only push the remaining tasks.

How Long Does It Take?

With 199 tasks and a 150ms delay between each, a full push takes approximately 30–60 seconds for new projects. Subsequent runs (mostly skips) complete in a few seconds.

9. Phase 4 — Done

Results Summary

  • Created — all tasks successfully added to Hubstaff
  • Skipped — tasks that already existed (not duplicated)
  • Failed — tasks that encountered errors (error message shown)

Saving Project IDs

If new projects were auto-created, a yellow box shows the new IDs in .env format. Copy these and add them to your .env file so future pushes reuse the same projects:

HUBSTAFF_PROJECT_CMS485=12345678
HUBSTAFF_PROJECT_OASIS=12345679
HUBSTAFF_PROJECT_QAPI=12345680
HUBSTAFF_PROJECT_VERSIONS=12345681
HUBSTAFF_ORG_ID=9876543

Going Back

Click "Back to Staging" to return to the task selector. The system will re-fetch existing tasks from Hubstaff so the "already exists" badges are updated.

12. Task ID Format & Idempotency

ID Format

Every task has a globally unique ID using this naming convention:

PrefixProjectExample
EVT-Regulatory Calendar (main)EVT-GV-2026-0108-ANNPKT
CMS485-CMS-485 Plan of CareCMS485-FM-001
OASIS-OASIS AssessmentsOASIS-WF-002
QAPI-QAPI ProgramQAPI-PIP-003
VER-Version HistoryVER-V5-FEATURES-001

How Idempotency Works

Every task is pushed to Hubstaff with its ID embedded in the task summary as a bracket tag:

[EVT-GV-2026-0108-ANNPKT] Annual Governance Packet Review

Before pushing, the system:

  1. Fetches all existing tasks from the target project (paginated, all pages)
  2. Extracts the bracket-tag IDs from each existing task's summary
  3. Marks any matching task as "ALREADY EXISTS" in the staging UI
  4. Skips those tasks during the push — no duplicate is ever created
Safe to run multiple times. Whether you run the push once, abort midway, or run it 10 times — the result is always the same: exactly one copy of each task in Hubstaff.

13. Troubleshooting

❌ "Hubstaff not connected" / "HUBSTAFF_PAT not configured"

Cause: The HUBSTAFF_PAT environment variable is missing or blank.

Fix:

  1. Open C:\AI\Git\training\HomeHealth\Policies_and_Procedures\.env
  2. Add HUBSTAFF_PAT=your_token_here
  3. Close the API Server window and rerun npm run server
  4. Refresh the browser

❌ "Hubstaff 401" error during push

Cause: The PAT token is expired or invalid.

Fix: Generate a new PAT in Hubstaff (see Section 4) and update .env.

❌ "Hubstaff 403" on project creation

Cause: The PAT doesn't have write scopes, or the Org ID is wrong.

Fix: Ensure the PAT has Hubstaff and Hubstaff Tasks write scopes enabled. Verify the Org ID in the Review screen.

❌ API Server not starting (port 8787 in use)

Cause: A previous server process is still running.

Fix: Open Task Manager → find node.exe processes → End task. Then relaunch.

❌ Vite dev server not starting (port 5173 in use)

# PowerShell — find and kill the process using port 5173
netstat -ano | findstr :5173
taskkill /PID <pid> /F

❌ Tasks fail with "project not found"

Cause: A saved project ID in .env is invalid (project was deleted in Hubstaff).

Fix: Remove the HUBSTAFF_PROJECT_* line for that project from .env. On next push, the system will auto-create a new project.

❌ "Select all" selects tasks marked ALREADY EXISTS

This is expected — "Select All" selects the checkboxes, but the push step will still skip tasks marked as "ALREADY EXISTS". They will appear in the Results as "Skipped", not "Created".

❌ Push stops midway / seems hung

Click Abort. Wait 10 seconds for the rate limiter to clear. Then go back to Staging and push again — only incomplete tasks will be created.
