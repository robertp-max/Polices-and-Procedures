# Reference Capture Protocol

**Purpose:** Standardize screenshot and visual-reference evidence for implementation PRs and phase sign-off.

**Applies To:** Phase 1 Dashboard reconstruction and all subsequent reconstructed surfaces.

---

## 1) Required Capture Sets

Each implementation PR must attach:

1. **Before captures** (baseline before code changes)
2. **After captures** (same routes/states after code changes)
3. **Playwright regression captures** (generated by required suites)

Minimum device contexts:
- Desktop (>=1440px)
- Laptop (1024-1439px)
- Mobile (<=767px)

Minimum modes:
- Dark mode
- Light mode

---

## 2) Naming Convention

Use deterministic naming:

`<surface>-<state>-<viewport>-<mode>-<before|after>.png`

Examples:
- `dashboard-default-desktop-dark-before.png`
- `dashboard-default-desktop-dark-after.png`
- `dashboard-kpi-mobile-light-before.png`
- `dashboard-kpi-mobile-light-after.png`

---

## 3) Required States for Dashboard

- Default dashboard load
- KPI block visible
- Command/action area visible
- At least one interactive focus state
- Mobile stacked layout

---

## 4) PR Evidence Requirements

Every PR must include:

1. File paths to before/after captures
2. File paths to Playwright capture artifacts
3. One short paragraph describing visual deltas
4. Confirmation that constrained page view and mobile no-scroll rules were verified

---

## 5) Sign-off Rule

No implementation PR may be approved without evidence paths and required before/after comparisons.

If captures are missing, PR status is **Not Ready for Review**.

---

## 6) Storage Location

Store captures in project-approved screenshot/report locations used by existing UAT and regression workflows.

Document exact paths directly in PR description and in phase report artifacts.
