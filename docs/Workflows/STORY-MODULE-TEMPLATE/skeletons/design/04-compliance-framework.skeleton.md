# Skeleton — design/04-compliance-framework.md

**Purpose:** instantiate the universal compliance invariants for THIS module's subject matter, and produce the audit checklist Phase-3 verifiers run against every storyboard.
**Exemplar:** `docs/GAO-001-A-New-Journey/design/04-compliance-framework.md`
**Inputs:** catalog row (`policyRefs`/`cmsRefs`), recon/content-inventory, invariants §§2–6.

## Required sections

1. **Wording guardrails instantiation** — the invariants §2 table plus this module's own completion-state names ("[Subject] Practice Complete" per scene) and any subject-specific near-miss risks (e.g. an eSign-adjacent module must also ban "signature captured").
2. **Citation map (per scene)** — table: scene / may cite / framing line (following the invariants §4 template, with the correct plain-English label) / must NOT cite or mislabel. Every `cmsRefs` and `policyRefs` entry from the catalog appears somewhere; citations are introduced where earned, never front-loaded.
3. **Verbatim sentence requirements** — which invariants-§5 sentences apply to this module (mandatory-reporting sentence if abuse/neglect content appears; module-specific verbatim units if the assessment tests recognition), with placements.
4. **Scenario realism limits** — for each depicted scenario in this module: may depict / must depict / must NOT depict, following invariants §6's register. HR-subject modules (harassment, substance, grievance) write these with the same restraint rules as clinical ones.
5. **Audit checklist** — the verifier's checkbox list, organized A (wording) / B (state-write) / C (citations) / D (verbatim sentences) / E (scenario realism) / F (redundancy) / G (canonical identity), with the verdict rule: any A–D failure = automatic FAIL. Copy GAO-001's structure; make every box concrete to this module.

## Done when

A hostile reviewer can verify any storyboard against section 5 without reading the invariants file; the citation map covers every catalog ref; no scenario in the module lacks realism limits.
