# Skeleton — design/05-learning-framework.md

**Purpose:** what each scene teaches, how the module's assessment is served, and the pacing budget.
**Exemplar:** `docs/GAO-001-A-New-Journey/design/05-learning-framework.md`
**Inputs:** recon/content-inventory (incl. assessment inventory), design/02 template assignments, invariants §12.

## Required sections

1. **Learning objectives per scene** — 2–4 behavioral objectives per scene, each traceable to inventory concepts (identify / apply / execute / contrast — not "understand").
2. **Assessment alignment map** — depends on the catalog `method`:
   - `Quiz`: table Q# / tests / scene / node / coverage strength. Quiz preserved unchanged; weak alignments get a "strengthen the node script" action, never a quiz edit. Flag any question with no teaching home as a CRITICAL finding.
   - `ReturnDemo` / `Scenario` / `CaseStudy` / `SkillsCheckoff` etc.: map each assessed behavior to the scene interaction that rehearses it — the scene must *rehearse the assessed behavior*, not just describe it.
   - `None`: objectives + distributed retrieval moments only; say where the retrieval moments land.
3. **Interaction-learning fit** — table: scene / pattern / learning type (recognition, judgment, procedure, consolidation) / why it fits / feedback design. Wrong-answer feedback always explains why the tempting choice fails (invariants §12).
4. **Pacing budget** — per-scene minutes / max concepts / max nodes, summing to the module's duration intent. Recap scenes carry zero new concepts.
5. **Retention devices** — the spaced re-exposure plan for assessment-critical concepts (compact rule → procedural depth → applied judgment → retrieval cue), transfer-test callbacks to earlier scenes, and cross-module callbacks to universe canon where earned.

## Done when

Every assessment item has a mapped teaching home with stated strength; the pacing table sums correctly; every judgment scene has a plausible-wrong-answer design.
