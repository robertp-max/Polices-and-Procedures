## 5. What Was Wired Durably

V3 CES Task Detail now exposes a Phase 4C-A adapter panel with:

- `data-qa="ces-durable-adapter-status"`
- `data-qa-persistence-mode="local-store"`
- store name and adapter event/task IDs
- evidence and approval counts from the local persisted app store
- audit/history mode

Safe local persisted store writes:

- `persist-viewed`: materializes adapter task if needed and appends an app-store audit/history row.
- `persist-started`: materializes/updates adapter task to `in_progress`.
- `persist-note`: writes an event note and task audit/history row.
- `persist-blocker`: writes a persisted blocker and task status.
- `clear-persisted-blocker`: clears the persisted blocker through the store transition path.
- `persist-evidence-placeholder`: writes metadata through the existing evidence store path only.
- `request-approval`: writes an app-store approval request only.

## 8. Completion Gate Logic

The adapter exposes:

- `data-qa="ces-completion-gate"`
- `data-qa-completion-ready="true|false"`
- `data-qa="ces-durable-blocker"`
- `data-qa-blocker-code="..."`

The gate blocks durable app-state completion unless all required conditions are satisfied in durable or verified adapter state:

- required forms/evidence satisfied
- persisted evidence/reference exists when required
- required signatures satisfied
- approval satisfied
- no seeded or persisted blocker
- app-store audit/history reference exists

When the gate is false, `Complete task` remains disabled. If the gate ever passes, the enabled label is `Complete in durable app-state`, not production complete.
